# SOP 10：每日开工与收工

> 适用：每次在车上（Jetson）开始和结束工作。安装步骤见 [docs/02 第 1 节](../02_ClaudeCode工作流.md)，安全规范见 [SOP 00](00_安全规范.md)。
> 状态：2026-10-20 按实际安装结果编写。开工第 1–4 步已经实际操作过；`/session-start`、`/session-end` 在 Jetson 上还没有用过（**未验证**）。

## 1. 开工

| 步骤 | 在哪里 | 命令 / 操作 | 期望看到 | 不对时查什么 |
|---|---|---|---|---|
| 1 上电 | 车上 | Jetson 上电；今天要上车的话，底盘也上电，遥控器开机放在手边 | Jetson 风扇转起来 | — |
| 2 登录 | PC 的 PowerShell | `ssh kuper@192.168.43.6` | 不要密码，提示符变成 `kuper@kuper` | 连不上：手机热点可能给 Jetson 换了 IP，到 Jetson 上运行 `hostname -I` 查看；要密码：免密钥没装好，见 docs/02 第 1 节 |
| 3 进 tmux | Jetson | `tmux new -A -s car` | 屏幕底部出现绿色状态栏；有现成的会话会直接接上 | — |
| 4 拉代码并启动 | Jetson | `cd ~/slam_car_tracking && git pull --ff-only && claude` | 出现 Claude Code 的输入框 | `git pull` 报错：本地有没提交的改动，先 `git status` 看看；`claude` 找不到：`~/.zshrc` 里少了 `~/.local/bin`，见 docs/02 第 1 节 |
| 5 同步进度 | Claude | `/session-start <今天想做的事>` | 汇报当前阶段、上次停在哪里，列出今天 3–5 个任务（每项写明产出、验收方式、要不要上车） | — |
| 6 确认计划 | Claude | 看完计划后回复确认或修改 | 计划确认后，它才开始改代码 | — |

想接着上一次的对话聊，第 4 步用 `claude --continue`。一般开新对话就行，进度靠工作日志衔接。

## 2. 工作中

| 你负责 | Claude 负责 |
|---|---|
| 定目标、确认计划、做决策 | 出方案、写代码、编译、跑测试 |
| **一切让车动的操作**、拿遥控器、拍急停 | 只读的检查（`candump`、`rostopic hz/echo`、`rosbag info`） |
| 车上的观察：轮子往哪转、卷尺读数、有没有异响 | 分析 bag 数据，对照验收门槛逐项判断 |
| 接线、上电、架空或落地 | 写工作日志，提交并推送 git |

常用命令：
| 场景 | 命令 |
|---|---|
| 要上车测试 | `/field-test <测试名>` 生成测试单 → 你按测试单操作、录 bag → 告诉 Claude bag 文件名，让 bag-analyst 分析 |
| 阶段验收 | `/phase-gate P0`（P0 换成当前阶段） |
| 换一件不相关的事 | 先 `/session-end` 收尾，再 `/clear` |

规矩：
- 让车动的命令（`rostopic pub /cmd_vel*`、`cansend`、启动 teleop/repeat 类 launch），Claude 只会写出来，并说明车要处于什么状态。**你确认车的状态之后**，再让它执行，或者你自己执行
- **车动的时候遥控器一定在手上**：Wi-Fi 可能卡顿，随时准备拨 SWA 接管
- 弹出权限确认时，看清楚再批准（通常是 `sudo`、安装软件这类操作）
- **代码只在 Jetson 上改**，PC 上不改代码，避免两边同时改 main

## 3. 收工

| 步骤 | 在哪里 | 命令 / 操作 | 期望看到 |
|---|---|---|---|
| 1 收尾 | Claude | `/session-end <你在车上看到的现象（可选）>` | 清理垃圾、写工作日志、提交并推送，最后报告 commit hash |
| 2 退出 | Claude | `/exit` | 回到 shell |
| 3 离开 tmux | Jetson | 按 `Ctrl-b`，松开后再按 `d` | 回到普通 SSH 终端；tmux 会话留在后台，下次 `tmux new -A -s car` 接上 |
| 4 断电 | 车上 | 底盘断电；Jetson 要关机的话，先执行 `sudo shutdown now`，等它关好再断电 | — |

## 4. 意外情况
| 现象 | 处理 |
|---|---|
| SSH 断线 | 重新 `ssh kuper@<IP>`，再 `tmux new -A -s car`，Claude 还在原来的地方 |
| 忘了运行 `/session-end` 就断电了 | 下次开工后先运行 `git status`。有没提交的改动，就让 Claude 补写日志并提交 |
| 车的动作和预期不一样 | 立刻拍急停或拨 SWA；然后告诉 Claude 你看到的现象，不要直接重试 |

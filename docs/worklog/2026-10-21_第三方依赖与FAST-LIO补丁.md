## 4. 问题与根因
- **现象**：livox_ros_driver2 master（`21445540`，2026-09）配 SDK v1.2.5 编译失败，`pub_handler.cpp:135` 报 `kLivoxLidarTypeMid360s` 不是成员，还缺 DoubleEcho 相关定义
  **根因**：master 需要 SDK v1.3.1（2026-04）。已确认：`git grep` 显示 SDK 到 v1.3.1 才有 Mid360s
  **处置**：驱动退回 `6b9356c`（2024-09），不升级 `/usr/local` 里的 SDK（commit `a7c7df0`）
- **现象**：fastlio_mapping 和驱动同时加载 boost_filesystem / boost_iostreams 的 1.71 和 1.80，链接器警告 may conflict
  **根因**：`/usr/local` 里有 boost 1.80（2026-03-11 安装，只有 `~/projects/pcl` 自编的 PCL 1.15 在用），gcc 和 CMake 都会优先用它（已确认）
  **处置**：用户用 sudo 脚本把它移到 `/opt/boost-1.80`（可以移回）；catkin clean 重编后 `ldd` 只剩 1.71；check_env 新增这一项检查（commit `a7c7df0`）。副作用：运行 `~/projects/pcl` 的程序需要设 `LD_LIBRARY_PATH=/opt/boost-1.80/lib`
- **现象**：FAST_LIO 的 `publish_odometry` 先 publish、后填协方差，所以发出的 `/Odometry` 带的是上一帧的协方差
  **根因**：上游代码问题（读源码确认）
  **处置**：没有修。P2 的 `lio_odom_bridge` 如果要用协方差，需要注意这一点
- **现象**：驱动 `/livox/imu` 的 `frame_id` 写死为 `livox_frame`，和 URDF 计划的 `livox_imu` 对不上
  **处置**：未解决，P2 设计 URDF 时处理（见 docs/01 第 1.3 节）
- **现象**：用户在聊天里发了 sudo 密码
  **处置**：Claude 没有使用也没有保存，并提醒以后不要在聊天里发
- ros-reviewer 审查结果：
  - 必须修 3 条：SOP 里 `rospack find` 一次传了两个包；docs/01 里"前提成立"说过头了；日志还没写（即本篇）——全部处理
  - 建议修第 4–7 条：SDK 安装标记文件；先读进 `REPOS` 变量防止假阳性；restore 改为反向应用补丁并检测手工改动；P2 launch 要显式写 `tf_publish_en: false`、rosparam 要在 `<node>` 外面加载——全部处理

### 1.1 包划分

`ros_ws/src/`（我们自己的代码）：

| 包 | 语言 | 职责 | 阶段 |
|---|---|---|---|
| `yhs_can_msgs` | msg | 厂家消息（仅用于调试对照） | 已有 |
| `fw_chassis` | C++ | SocketCAN 收发、协议编解码（✅ 已完成并测试）、`/cmd_vel`→ctrl_cmd、50 Hz 心跳与超时看门狗、`/wheel/odom`、`/chassis/state`、diagnostics | P1 |
| `fw_description` | xacro | URDF：`base_footprint`、`base_link`、`livox_frame`（倒装）、`livox_imu`、`oak-d-base-frame` | P2 |
| `fw_localization` | C++ | `lio_odom_bridge`（FAST-LIO 位姿 → `odom→base_footprint`）、`map_localizer`（先验地图配准 + 全局重定位 + 定位状态）。位姿换算、2D 投影、配准门限、分支定界都写成纯函数配 gtest | P2–P3 |
| `fw_bringup` | launch/yaml | `base.launch`（底盘 + 雷达 + RSP）、`lio.launch`、`mapping_record.launch`、`localization.launch`、`teach.launch`、`repeat.launch`；Mid-360 驱动配置、FAST-LIO 参数 | P2–P4 |
| `fw_navigation` | C++/Py | `path_recorder`、`path_follower`、`safety_guard`、move_base 配置 | P4 |
| `fw_tools` | Python | 标定脚本（地面拟合求外参）、离线建图后处理、bag 指标分析（LIO 漂移、地图质量、定位重复性、跟踪误差） | 贯穿各阶段 |

第三方源码（Livox-SDK2、livox_ros_driver2、FAST_LIO、small_gicp，以及参与比选的建图后端）**不放进 `ros_ws/src`**：
- `thirdparty/repos.yaml`（vcstool 格式）固定每个仓库的 commit
- 我们对它们的修改存成 `thirdparty/patches/<仓库>/*.patch`
- `tools/setup_thirdparty.sh` 负责拉取、打补丁，并编译到 `thirdparty_ws/`（不入库）；Livox-SDK2 装到 `/usr/local`
- `ros_ws` 叠加在 `thirdparty_ws` 之上（`catkin config --extend`）

launch 严格分层，每一层只 include 下一层一次，不允许绕过分层单独启动其中的节点（否则会出现重复节点，或者某个 TF 没有发布者）：
```
base.launch            底盘 + Mid-360 驱动 + robot_state_publisher
 └ lio.launch          + FAST-LIO2 + lio_odom_bridge
    ├ mapping_record.launch   + rosbag record（建图用的原始数据）
    └ localization.launch     + map_localizer + map_server
       ├ teach.launch         + path_recorder
       └ repeat.launch        + path_follower + safety_guard
```

### 1.2 坐标系与接口约定（写入 CLAUDE.md，作为硬规则）

- TF 树：`map → odom → base_footprint → base_link → {livox_frame → livox_imu, oak-d-base-frame → …}`
- **每个 TF 只能有一个发布者**：
  - `map→odom`：只由 `map_localizer` 发布，且只通过 `localization.launch` 启动（teach/repeat 经 include 得到它）。建图是离线做的，录包时不需要在线的 map 坐标系。`map_localizer` 以 ≥ 20 Hz 用当前时间重复发布最近一次的修正（配准本身只有 2–5 Hz，否则下游查询 TF 会报外推错误）；`INITIALIZING` 期间不发布
  - `odom→base_footprint`：只由 `lio_odom_bridge` 发布。FAST-LIO 自带的 `camera_init→body` TF 广播必须用补丁关掉
  - 其余全部来自 robot_state_publisher（URDF）。雷达倒装体现在 URDF 里 `livox_frame` 的 roll = π
- `lio_odom_bridge` 的换算：odom 原点 = 开机时的 `base_footprint`（要求开机时车停在平地上）。设 `T_fb` 为 URDF 中 `base_footprint→livox_imu` 的外参（FAST-LIO 的 body 坐标系就是 IMU 坐标系），则 `T_odom_base(t) = T_fb · T_ci_body(t) · T_fb⁻¹`，再投影到 2D（保留 x、y、yaw）。这个换算写成纯函数并测试（用例至少包括：`T_ci_body = I` 时结果为 I；倒装 + IMU 偏心时原地纯旋转，base 平移为 0；前进 1 m 时 yaw 不变）。公式成立的前提：所用 FAST_LIO 版本没有对 camera_init 做重力对齐（P2 核实）；IMU 初始化期间车完全静止；`T_fb` 和 FAST-LIO 内部用的雷达–IMU 外参一致
- 外参唯一来源是 URDF：FAST-LIO yaml 里的 `extrinsic_T/R` 必须和 URDF 的 `livox_frame→livox_imu` 一致，用一个一致性测试保证，不允许两处各改各的
- `map_localizer` 计算 `map→odom` 时，用的是 bridge 发布的、已经投影到 2D 的 `odom→base_footprint`（按点云时间戳从 TF 查），不用原始的 3D `/Odometry`，否则 z、roll、pitch 的残差会被吸进 `map→odom`，造成慢速抖动
- FAST-LIO 重启或发散时，odom 原点会变化：bridge 要检测到这件事，`map_localizer` 要重新初始化，`/localization/status` 在此期间不是 `OK`
- `/localization/status`：`OK` / `DEGRADED` / `LOST` / `INITIALIZING`，同时给出配准得分（自定义消息，类型在 P3 设计时确定）。跟随器和 `safety_guard` 只要看到不是 `OK` 就停车，**超过 0.5 s 没收到 status 等同于 `LOST`**；`path_recorder` 在不是 `OK` 时暂停记录。`DEGRADED` 目前只用于诊断，下游行为和 `LOST` 一样；以后要改成"减速继续"，必须有数据支持并由用户决定
- `safety_guard` 的点云直接来自驱动的原始数据（`/livox/lidar`，在 `fw_navigation` 里自己做 CustomMsg 裁剪），**不经过 FAST-LIO**：FAST-LIO 的预处理有盲区过滤和降采样，而且安全层不能依赖 LIO 是否正常
- **bag 回放规则**：离线重跑 FAST-LIO、`map_localizer`、建图后端时，**不能回放 bag 里的 `/tf`**（否则同一个 TF 会有两个发布者）。用 `rosbag play --topics /livox/lidar /livox/imu /wheel/odom /chassis/state`，静态 TF 由回放端的 robot_state_publisher 按当前 URDF 提供。专门用于离线比选的 bag 不录 `/tf`
- ROS 侧一律使用 SI 单位与 REP-103（rad/s，逆时针为正）。°/s 和符号修正**只在 `fw_chassis` 内部**做一次，参数名为 `angular_sign`
- 速度链路：各控制器 → `/cmd_vel_nav`、`/cmd_vel_move_base` → `safety_guard` → `/cmd_vel` → `fw_chassis`。只有 `safety_guard` 可以发布 `/cmd_vel`
- 底盘使用 6 档（4T4D），只接受 vx + wz；`linear.y` 被忽略并打印警告

### 1.3 各层选型评估（2026-10-20，按效果选）

原则：不因为"沿用方便"选方案；看不出明显优劣的地方，**在同一组 bag 上实测比选**，用 `fw_tools` 的指标脚本定胜负，结果写进工作日志。

| 层 | 候选 | 结论与理由 |
|---|---|---|
| 主传感器 | Mid-360 水平安装 / **倒装** | **倒装**。Mid-360 垂直视场 −7°~+52°（手册 p.20）。水平安装时，装在 0.4 m 高处，一个 0.2 m 高的箱子在 1.6 m 以内就看不到了，`safety_guard` 会漏掉它。倒装后视场为 −52°~+7°，墙面仍在视场内，代价是看不到天花板。手册要求倒装时安装面离地 ≥ 0.5 m（p.9），原点距安装面 47 mm，所以原点离地 ≥ 约 0.45 m，地面盲区半径 ≈ 0.45 / tan52° ≈ 0.35 m（从雷达中心算起；车身本身占掉多少，P2 实测） |
| 激光惯性里程计 | **FAST-LIO2** / Point-LIO / LIO 结果再送进 EKF | **FAST-LIO2**。车速 ≤ 0.3 m/s，Point-LIO 的高带宽优势用不上；FAST-LIO2 本身就是紧耦合的迭代卡尔曼滤波，再套一层 EKF 只会增加坐标系转换和协方差调参，精度不会提高。IMU 用 Mid-360 内置的那颗（与雷达同一时钟，外参固定） |
| 轮式里程计 | — | 保留 `/wheel/odom`，但不参与 TF。用于同场对照、诊断，以及将来 LIO 退化时兜底（P5） |
| 建图 | ① FAST-LIO2 单独建图 ② FAST-LIO2 + 位姿图闭环（关键帧 + GICP 闭环验证 + GTSAM）③ GLIM（带全局优化，支持 Mid-360） | ① 没有闭环，存在累积漂移，可能出现双墙，**排除**。**②、③ 在同一组 bag 上实测比选**。建图改为"上车录 bag → 离线建图"：同一份数据可以反复调参、换算法，不用每次重新开车 |
| 先验地图定位 | **L1** FAST-LIO2 里程计 + 当前帧对先验地图做 GICP（small_gicp，2–5 Hz）→ `map→odom` <br> **L2** 把先验地图载入 FAST-LIO2 的 ikd-tree，地图冻结，紧耦合定位 <br> L3 hdl_localization（UKF + NDT） | **L1 为默认，L2 为挑战者，两者实测比选**。L1 的里程计和地图校正解耦，`map→odom` 语义清楚，家具挪动时也稳健；L2 每帧的精度可能更高，但地图和现场不一致时会被拉偏，而且要改 FAST-LIO 源码。L3 的 IMU 预测弱于 FAST-LIO，只作为备用。如果 L2 胜出，要先重新定义 TF 归属，修改 CLAUDE.md 规则 1 后再落地 |
| 全局重定位 | 手动 2D Pose Estimate / Scan Context / FPFH + TEASER++ / **2D 分支定界 + 3D GICP 精配** | **2D 分支定界 + GICP**。室内是单层平面：把当前帧按高度带压成 2D，在 2D 栅格地图上对 (x, y, yaw) 做分支定界全局搜索，再用 3D GICP 精配验证。不依赖描述子训练，可以写成纯函数配测试。手动给初值作为兜底 |
| 2D 地图 | — | 由 3D 地图按高度带投影生成 `map.pgm/yaml`，只用于显示、示教，以及 P4 以后的 move_base。**不再用 AMCL** |
| 路径跟随 | 自研 **Regulated Pure Pursuit** | 不变：ROS1 没有官方 RPP，自研的逻辑透明、容易调；需要绕障时（P5）再上 move_base_flex + TEB |
| 安全 | 独立的 `safety_guard` 节点 | 不变；输入从 `/scan` 改为驱动原始点云的裁剪盒（倒装后近场可见，不经过 FAST-LIO），再加上定位状态 |
| 构建 | `catkin build`（catkin_tools）+ `thirdparty_ws` 叠加 | 第三方源码固定 commit、修改存成补丁，可以复现，也不会把别人的代码混进我们的包 |

**待核实**（P0/P2 第一步就验证，结论写进 `docs/hardware/Livox_Mid-360速查.md` 或工作日志，不能凭记忆写）。2026-10-21 读 `thirdparty/repos.yaml` 固定版本的源码核实了一部分：

- [ ] **架空测试**（车轮离地）：按 [SOP 01](sop/01_上电与CAN链路检查.md) 下发 `wz=+0.2 rad/s`，记录车轮转向和 `ctrl_fb` 的符号，确定 `angular_sign`
- [ ] **原地旋转测试**：6 档下 vx=0、wz≠0，观察四个轮子的转向角（`front_angle_fb`、`rear_angle_fb`）。结论决定 P4 跟随器用差速模型还是阿克曼模型
- [ ] **里程计标定**：直线 5 m 往返 3 次、原地（或最小半径）旋转 360° 3 次，用卷尺和地面标记测量
- **验收**：直线距离误差 < 2%；纯轮式里程计转 360° 的误差有记录（作为和 LIO 对照的基线）；`cmd_vel` 中断后 0.3 s 内停车；遥控器 SWA 拨回遥控模式时车立即听遥控器的；以上全部录 bag

### P2 雷达、URDF 与激光惯性里程计（3–4 天）
- [ ] Mid-360 驱动跑通：`/livox/lidar`（CustomMsg）、`/livox/imu`；驱动配置文件放在 `fw_bringup/config/`，不改驱动源码
- [ ] 时间同步：Jetson 上用 `ptp4l` 做 PTP 主时钟（**必须用 UDP/IPv4 传输**，雷达只支持这种，手册 p.14），雷达对时。测量方法：以 `/livox/imu` 的"接收时刻 − stamp"为准，并参考 ptp4l 日志里的 offset；点云帧的 stamp 是帧起始时间（待核实），只检查"stamp + 帧时长 ≈ 接收时刻"，不能直接拿点云的 stamp 和当前时间比
- [ ] 雷达支架：倒装，安装面离地 ≥ 0.5 m（手册 p.9），M3 × 4 + 定位孔，金属板 ≥ 3 mm 厚、四周留 ≥ 10 mm 散热空间；M12 接口朝车尾（雷达 −X 方向）
- [ ] `fw_description`：倒装外参先用卷尺测量，再用地面平面拟合求出 roll、pitch 和安装高度（`fw_tools/ground_calib.py`，平面拟合写成纯函数配 pytest）；`livox_frame→livox_imu` 外参取自手册：平移 (0.011, 0.02329, −0.04412) m，旋转为单位阵（手册 p.15）
- [ ] FAST-LIO2：mid360 参数（盲区、降采样、外参）放在 `fw_bringup/config/`；用补丁关掉自带 TF 广播并对接 livox_ros_driver2（补丁已有：`thirdparty/patches/FAST_LIO/`。launch 里仍要显式写 `publish/tf_publish_en: false`；FAST-LIO 用公有 NodeHandle 读参数，yaml 要像官方 launch 那样在 `<node>` 外面 `rosparam load`，放进 `<node>` 里会全部读不到、悄悄用默认值）
- [ ] `lio_odom_bridge`：按 1.2 节的公式发布 `odom→base_footprint` 和 `/odom/lio`；换算函数配 gtest（含倒装外参用例）
- [ ] 近场可见性：在原始点云里确认 0.1 m 高的矮箱在车前 0.3–1.5 m 范围内都能看到（验证 1.3 节的视场估算）
- [ ] 同场录 `/wheel/odom` 作对照；`fw_tools/lio_drift.py` 计算静止漂移、回到起点的误差，以及和轮式里程计的偏差
- **验收**（建议值）：`/livox/lidar` 10 Hz、`/livox/imu` ≥ 190 Hz；`/livox/imu` 的"接收时刻 − stamp" < 5 ms（按上面的方法测）；0.1 m 矮箱在 0.3–1.5 m 内可见；地面拟合残差 < 1 cm / 0.5°；静止 5 分钟漂移 < 1 cm / 0.2°；原地（或最小半径）转 3 圈回到起点 < 3 cm / 1°；5 m 往返 3 次，终点对地面标记 < 3 cm；车静止时 RViz 里的点云不晃动；FAST-LIO + 驱动 CPU < 1.5 核

### P3 建图与先验地图定位（4–5 天）
- [ ] `mapping_record.launch`：录建图用的 bag，同时实时显示 FAST-LIO 结果作为现场预览；SOP 规定路线和速度（≤ 0.3 m/s、转弯慢、回到起点闭环、经过 3 段已经用卷尺量过的距离）
- [ ] 离线建图：在同一组 bag 上比选建图后端 ②（FAST-LIO2 + 位姿图闭环）和 ③（GLIM），选出的方案和理由写进工作日志
- [ ] 后处理（`fw_tools`）：与重力对齐、体素 5 cm、去离群点、按高度带投影出 2D 栅格 → `data/maps/<场地>/{map.pcd, map.pgm, map.yaml, meta.yaml}`；meta 里记录外参、各第三方 commit、bag 名。PCD 控制在 20 MB 以内，超过再考虑 Git LFS
- [ ] `map_localizer`：L1 方案（small_gicp 对先验地图配准，2–5 Hz）；配准门限（得分、单次修正幅度）判定 `OK/DEGRADED/LOST`；全局重定位（2D 分支定界 + GICP）；关机时保存最后位姿，开机时优先用它，失败再做全局重定位；也支持 RViz 2D Pose Estimate 手动给初值
- [ ] L2 挑战者（FAST-LIO2 冻结地图模式），在同一组 bag 上和 L1 比选
- [ ] `localization.launch`：驱动 + FAST-LIO2 + `lio_odom_bridge` + `map_localizer` + map_server（只用于显示）
- [ ] 指标脚本：`map_quality.py`（闭合误差、墙面厚度、和卷尺距离对比）、`loc_repeatability.py`（地面贴 4 个标记点，每个点到访 10 次）、`loc_jitter.py`（`map→odom` 每次修正的幅度）
- **验收**：闭合误差 < 5 cm；墙面厚度 < 5 cm，没有重影或双墙；卷尺实测的 3 段距离误差 < 1%；标记点定位重复性 **< 3 cm / 1°**（原门槛 5 cm / 3°；收紧是因为 P4 要求横向误差 RMS < 5 cm，定位本身必须明显更准）；连续运行 30 分钟，`map→odom` 没有单次 > 5 cm / 2° 的跳变；在地图内任意 10 处开机做全局重定位，≥ 9 次在 10 s 内收敛到距标记 10 cm / 2° 以内；被搬动（绑架，不重启 FAST-LIO）后 5 s 内报 `LOST` 并开始重定位；定位链路 CPU 合计 < 2 核（含 P2 的 FAST-LIO + 驱动）

### P4 示教与复现：核心功能（4–5 天）
- [ ] `path_recorder`：遥控走一遍，在 map 坐标系下每 0.1 m 或 5° 记录一个位姿，保存为 `data/paths/<名称>.yaml`（带地图名和时间戳）
- [ ] `path_follower`（Regulated Pure Pursuit）：
  - 自适应前视距离 0.4–0.8 m；按曲率和障碍距离限速；终点减速并对准朝向
  - 横向误差 > 0.5 m 或 `/localization/status` 不是 `OK` 时停车并报警，不硬跟
  - 支持单次和循环模式；从路线上最近的点开始；暂停和恢复走 service
- [ ] `safety_guard`：点云裁剪盒的停车区和减速区（按车速动态伸缩）、防撞条、急停、遥控接管、定位丢失、看门狗；障碍物清除后保持 2 s 再放行
- [ ] `fw_tools/track_error.py`：从 bag 里计算横向误差的 RMS / 最大值，以及终点误差
- **验收**：30 m 级别的闭合路线**连续跑 10 圈**：横向误差 RMS < 5 cm、最大值 < 15 cm、终点误差 < 10 cm；在路线上放箱子（含 0.1 m 高的矮箱），100% 能停住（停车距离 ≥ 0.3 m），撤走后能自动继续；全程没有碰撞

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 4T4D 档下不能原地旋转 | P1 尽早实测；不行的话跟随器加最小转弯半径约束，示教时避免原地转向 |
| 遥控器优先级最高（SWA） | `/chassis/state` 暴露遥控模式；处于遥控模式时跟随器自动暂停 |
| 长走廊等几何特征少的场景导致 LIO 退化 | Mid-360 是 360° 视场，可以缓解；P3 指标里关注这类区段；P5 做退化检测和轮式里程计兜底 |
| 雷达和系统时间不同步（TF 外推报错、bag 分析对不上） | P2 用 PTP 对时，并把时间差列为验收项 |
| 场地变化（家具挪动）导致定位变差 | L1 方案对局部变化更稳健；配准得分低于门限就报 `DEGRADED` / `LOST` 并停车；场地有较大变化时重新建图 |
| 倒装后车周围地面仍有约 0.35 m 盲区（从雷达中心算起）；手册说明 0.1–1 m 内低反射率、细小的物体（黑色泡沫、细线等）不保证检出；玻璃、镜面让激光失效 | 防撞条兜底；P5 接入 OAK 深度和超声波（协议里已有，需确认是否安装了探头） |
| 原始点云 bag 体积大（每小时约 10–20 GB，待实测） | 只在建图和定位比选时录原始点云；日常测试的录包列表以 `/field-test` 命令里的为准 |
| 第三方代码（FAST_LIO 等）升级后行为变化 | `thirdparty/repos.yaml` 固定 commit；升级要单独提交，并用存档 bag 回归 |
| Jetson 访问外网不稳定（影响 Claude Code、apt、拉取第三方源码） | 配好代理；先在 PC 上下载 deb 和源码 |

# v2 技术路线与里程碑

> 目标：**室内建图 → 示教一条路线 → 小车在地图上定位并反复沿这条路线行驶；有障碍时停车，障碍移走后继续。**
> 平台决策（2026-10-18 确认）：Jetson Orin NX + JetPack 5.1.1（L4T R35.3.1，Ubuntu 20.04）+ **ROS1 Noetic** · 新增 **2D 激光雷达** · 不考虑 FMQL30TAI 移植。

## 1. 系统架构

```
                    ┌──────────────── 定位层 ────────────────┐
 2D LiDAR ─/scan──► │ slam_toolbox（建图） / AMCL（定位）     │──► TF map→odom
                    └────────────────────────────────────────┘
 OAK-D Pro ─/imu──┐
                  ├──► robot_localization EKF ─────────────────► TF odom→base_footprint
 fw_chassis_node ─/wheel/odom┘
       ▲  │                               示教：path_recorder ──► data/paths/<名称>.yaml
       │  └─/chassis/state（急停/遥控/防撞条/电量/故障）
       │                                  复现：path_follower（Regulated Pure Pursuit）
  CAN  │                                              │ /cmd_vel_nav
       │                                              ▼
 FW-mini-pro ◄── /cmd_vel ◄── safety_guard（激光近距停车 · 防撞条 · 急停 · 遥控接管 · 限速）
                                              ▲
                          move_base（回到路线起点 / 自由导航，P4 以后）─/cmd_vel_move_base
```

### 1.1 包划分（`ros_ws/src/`）

| 包 | 语言 | 职责 | 阶段 |
|---|---|---|---|
| `yhs_can_msgs` | msg | 厂家消息（仅用于调试对照） | 已有 |
| `fw_chassis` | C++ | SocketCAN 收发、协议编解码（✅ 已完成并测试）、`/cmd_vel`→ctrl_cmd、50 Hz 心跳与超时看门狗、`/wheel/odom`、`/chassis/state`、diagnostics | P1 |
| `fw_description` | xacro | URDF：`base_footprint`、`base_link`、`laser_link`、`oak-d-base-frame`、`imu_link` | P2 |
| `fw_bringup` | launch/yaml | `base.launch`（底盘 + 传感器 + EKF + RSP）、`mapping.launch`、`localization.launch`、`teach.launch`、`repeat.launch` | P2–P4 |
| `fw_navigation` | C++/Py | `path_recorder`、`path_follower`、`safety_guard`、move_base 配置 | P4 |
| `fw_tools` | Python | 标定脚本、rosbag 指标分析（odom 误差、跟踪误差、定位跳变） | 贯穿各阶段 |

### 1.2 坐标系与接口约定（写入 CLAUDE.md，作为硬规则）

- TF 树：`map → odom → base_footprint → base_link → {laser_link, oak-d-base-frame → …, imu_link}`
- **每个 TF 只能有一个发布者**：`map→odom` 由 AMCL 或 slam_toolbox 发布（二者不能同时运行），`odom→base_footprint` 只由 EKF 发布，其余全部来自 robot_state_publisher。
- ROS 侧一律使用 SI 单位与 REP-103（rad/s，逆时针为正）。°/s 和符号修正**只在 `fw_chassis` 内部**做一次，参数名为 `angular_sign`。
- 速度链路：各控制器 → `/cmd_vel_nav`、`/cmd_vel_move_base` → `safety_guard` → `/cmd_vel` → `fw_chassis`。只有 `safety_guard` 可以发布 `/cmd_vel`。
- 底盘使用 6 档（4T4D），只接受 vx + wz；`linear.y` 被忽略并打印警告。

### 1.3 关键选型与理由

| 环节 | 选择 | 理由 / 备选 |
|---|---|---|
| 2D 激光雷达 | **思岚 RPLIDAR C1**（预算方案，约 12 m）或 **S2**（约 30 m，抗强光） | 两者都由 `rplidar_ros` 驱动；购买前确认所用驱动版本支持 ROS1 Noetic。乐动 LD19 更便宜，可作备选。价格以购买时为准 |
| 雷达安装 | 车顶中心附近，360° 无遮挡，高约 0.3–0.4 m | 尽量让 laser_link 落在 base_link 正上方，减小外参误差的影响 |
| 建图 | **slam_toolbox**（`ros-noetic-slam-toolbox`） | 闭环稳定，支持地图序列化后继续建图；Cartographer 精度更高但调参成本大，作为备选 |
| 定位 | **AMCL** + EKF 里程计 | 成熟、轻量、容易诊断；slam_toolbox 的定位模式作为备选 |
| 里程计 | `ctrl_fb` 的 vx、wz + OAK BNO086 陀螺仪 → EKF | 4T4D 转向时会打滑，用陀螺仪约束航向 |
| 路径跟随 | 自研 **Regulated Pure Pursuit**（曲率限速、接近障碍减速、终点减速） | ROS1 没有官方 RPP。自研逻辑透明、容易调；需要绕障时（P5）再上 move_base_flex + TEB |
| 安全 | 独立的 `safety_guard` 节点 | 不依赖规划器是否正常工作 |
| 构建 | `catkin build`（catkin_tools） | 支持按包增量编译和 `catkin test`，也不需要顶层 CMakeLists 符号链接 |

## 2. 里程碑（每个阶段必须通过验收门槛才能进入下一阶段）

每个阶段收尾都要提交三样东西：**SOP 文档**（`docs/sop/`）、**工作日志**（`docs/worklog/`），以及**存档到 `data/bags/` 的 rosbag 和指标结果**。

### P0 环境与仓库（约 1 天）
- [ ] Jetson：`cat /etc/nv_tegra_release` 确认是 R35.3.1；设置 `nvpmodel` 和 `jetson_clocks`
- [ ] 安装 ROS Noetic（ros-base 即可）、`python3-catkin-tools`、`can-utils`、`ros-noetic-{robot-localization,slam-toolbox,amcl,map-server,move-base,rplidar-ros,depthai-ros}`（具体包名以 apt 为准）
- [ ] 用 systemd-networkd 让 can0 开机自动以 500 kbps 启动（`tools/setup_can.sh`）
- [ ] udev 规则：雷达 → `/dev/rplidar`，OAK → plugdev
- [ ] 安装 Claude Code，把仓库克隆到 `~/slam_car_tracking`，确认 `.claude/` 配置生效（见 [02_ClaudeCode工作流](02_ClaudeCode工作流.md)）
- **验收**：`catkin build && catkin test` 全绿（含 `fw_chassis` 的 15 个协议测试）；`candump can0 -n 50` 能看到 `18C4D1EF`，频率约 100 Hz

### P1 底盘驱动重写与标定（2–3 天）
- [ ] `fw_chassis_node`（C++）：
  - 订阅 `/cmd_vel`；内部 `steady_timer` 以 50 Hz 发送 ctrl_cmd（手册要求周期 10–50 ms）
  - 超过 `cmd_timeout`（默认 0.3 s）没收到命令就发零速；空闲超过 `park_after`（默认 5 s）就切到驻车档（1），有新命令时恢复 6 档
  - 解析 ctrl_fb，积分出 `/wheel/odom`（时间戳取接收时刻、单调时钟）；`publish_tf` 默认 false（TF 由 EKF 负责）
  - 发布 `/chassis/state`：急停、遥控控制、防撞条、SOC、故障等级；处于遥控模式或急停时打印节流警告
  - CAN 掉线时检测、报错并自动重连；CAN 接口名做成参数
  - 速度和加速度限幅做成参数
- [ ] **架空测试**（车轮离地）：按 [SOP 01](sop/01_上电与CAN链路检查.md) 下发 `wz=+0.2 rad/s`，记录车轮转向和 `ctrl_fb` 的符号，确定 `angular_sign`
- [ ] **原地旋转测试**：6 档下 vx=0、wz≠0，观察四个轮子的转向角（`front_angle_fb`、`rear_angle_fb`）。结论决定 P4 跟随器用差速模型还是阿克曼模型
- [ ] **里程计标定**：直线 5 m 往返 3 次、原地（或最小半径）旋转 360° 3 次，用卷尺和地面标记测量
- **验收**：直线距离误差 < 2%；纯轮式里程计转 360° 的误差有记录（作为 EKF 前的基线）；`cmd_vel` 中断后 0.3 s 内停车；遥控器 SWA 拨回遥控模式时车立即听遥控器的；以上全部录 bag

### P2 传感器、URDF 与 EKF（约 2 天）
- [ ] 雷达驱动和 `laser_link` 外参（卷尺测量；之后用地图里的墙面直线度复核）
- [ ] OAK 只开 IMU（不开深度，省算力和 USB 带宽）；`imu_link` 外参取自 depthai URDF
- [ ] EKF：wheel 提供 vx + vyaw，IMU 提供 vyaw；`two_d_mode`；`publish_tf: true`（TF 的唯一来源）
- [ ] 静止 5 分钟测 IMU 零偏和 EKF 航向漂移
- **验收**：车原地静止时 RViz 里的激光点不晃动；原地转 3 圈回到起点，EKF 航向误差 < 3°；静止时航向漂移 < 1°/min

### P3 建图与定位（约 3 天）
- [ ] `mapping.launch`：slam_toolbox 在线异步建图；SOP 规定路线和速度（≤ 0.3 m/s、回到起点闭环）
- [ ] 保存 `data/maps/<场地>/map.{pgm,yaml}` 和 posegraph
- [ ] `localization.launch`：map_server + AMCL；用 RViz 2D Pose Estimate 设初始位姿，也支持从参数加载上一次的位姿
- [ ] `fw_tools/loc_repeatability.py`：在地面贴 4 个标记点，每个点到访 10 次，记录定位输出
- **验收**：地图中没有重影或双墙；在标记点上的定位重复性 < 5 cm / < 3°；被搬动（绑架）后重新设初始位姿，能在 5 s 内收敛

### P4 示教与复现：核心功能（4–5 天）
- [ ] `path_recorder`：遥控走一遍，在 map 坐标系下每 0.1 m 或 5° 记录一个位姿，保存为 `data/paths/<名称>.yaml`（带地图名和时间戳）
- [ ] `path_follower`（Regulated Pure Pursuit）：
  - 自适应前视距离 0.4–0.8 m；按曲率和障碍距离限速；终点减速并对准朝向
  - 横向误差 > 0.5 m 或定位协方差过大时停车并报警，不硬跟
  - 支持单次和循环模式；从路线上最近的点开始；暂停和恢复走 service
- [ ] `safety_guard`：激光前向扇区停车区和减速区（按车速动态伸缩）、防撞条、急停、遥控接管、看门狗；障碍物清除后保持 2 s 再放行
- [ ] `fw_tools/track_error.py`：从 bag 里计算横向误差的 RMS / 最大值，以及终点误差
- **验收**：30 m 级别的闭合路线**连续跑 10 圈**：横向误差 RMS < 5 cm、最大值 < 15 cm、终点误差 < 10 cm；在路线上放箱子，100% 能停住（停车距离 ≥ 0.3 m），撤走后能自动继续；全程没有碰撞

### P5 鲁棒性与扩展（持续）
- [ ] OAK 深度点云 → costmap/safety（矮障碍、桌面这类悬空障碍）
- [ ] 路线上有障碍时绕行：move_base_flex 的 `exe_path` + TEB
- [ ] 开机自启（systemd），提供"选择地图 + 路线 + 开始/停止"的简易 CLI 或 Web 面板
- [ ] 多地图、多路线管理；低电量自动停止
- [ ] 回归测试：把各阶段录的 bag 离线回放，跑指标脚本，防止参数改动导致退化

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 4T4D 档下不能原地旋转 | P1 尽早实测；不行的话跟随器加最小转弯半径约束，示教时避免原地转向 |
| 遥控器优先级最高（SWA） | `/chassis/state` 暴露遥控模式；处于遥控模式时跟随器自动暂停 |
| 玻璃、镜面会让激光失效 | P5 接入超声波（协议里已有，需确认是否安装了探头）和深度相机 |
| 场地变化导致定位变差 | AMCL 的协方差超过阈值就停车；场地有较大变化时重新建图 |
| Jetson 访问外网不稳定（影响 Claude Code、apt） | 配好代理；先在 PC 上下载 deb 和模型 |
| 室内 rosbag 体积大 | 默认只录 `/scan /tf /tf_static /wheel/odom /imu /cmd_vel* /chassis/state /amcl_pose`，不录图像 |

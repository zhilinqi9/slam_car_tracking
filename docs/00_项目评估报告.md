# 项目评估报告（v1 代码全面 Review）

> 评估日期：2026-10-18 · 评估对象：git `bc3fa03` 时的 `FW-mini-pro-ros1/`（现已移至 [`legacy/v1_FW-mini-pro-ros1/`](../legacy/v1_FW-mini-pro-ros1/)）
> 对照资料：《FW-mini-pro 用户使用手册 V1.1.1》、《工作日志整合_v2.docx》、旧 README（[`legacy/README_v1.md`](../legacy/README_v1.md)）

## 1. 结论

**v1 效果差不是调参问题，而是架构问题。** 有三类根因叠加在一起，参数怎么调都绕不过去：

1. **运动学模型用错了。** 底盘是四转四驱（4T4D，双阿克曼），旧代码把它当成"全向底盘"配置规划器（日志里还写成"差速底盘"）。在 6 档下底盘直接丢弃 Y 方向速度，所以规划器算出来的轨迹底盘根本走不出来。
2. **TF 和定位链路有冲突。** `odom→base_link` 有两个发布者（EKF 和 RTAB-Map 视觉里程计），导航时 RTAB-Map 还会被启动两次。定位跳变、地图重影基本都是这里来的。
3. **感知能力不够，避障实际上没生效。** 只有一个前向约 70° 视场的 OAK-D Pro，USB2 降级时只有 10 fps，可信深度约 2 m。代价地图的障碍层因为参数命名空间写错是空的，就算写对了，观测源也只有约 1 Hz 的刷新。

另外还有一个工程层面的问题：**文档和代码不一致。** 工作日志里贴的代码（`invert_angular`、50 Hz、`base_local_planner_params.yaml` 等）和仓库里的实际代码对不上，已经没法判断当时车上跑的到底是哪一版。

**处置：** v1 只留作参考，不在它上面修补。v2 按 [01_技术路线与里程碑](01_技术路线与里程碑.md) 重建。可以复用的有：`yhs_can_msgs` 消息定义、CAN 帧编解码思路（已验证正确）、建图操作 SOP 的经验。

## 4. v2 的约束（由本次评估得出）

1. **底盘按"非全向、vx + wz 指令"建模**（6 档）。是否能原地旋转在 P1 实测，结果决定路径跟随器用差速模型还是阿克曼模型。
2. **每个 TF 只能有一个发布者**，写进 CLAUDE.md 作为硬规则，由 reviewer agent 检查。
3. **主定位传感器改为 2D 激光雷达**，OAK-D Pro 降级为 IMU 来源和补充避障传感器。
4. **安全层独立于规划层**：底盘急停、遥控接管、防撞条、激光近距停车，任何一项触发都直接把速度置零。
5. **代码是唯一事实来源**：工作日志只能引用 commit hash 和实测数据，不在日志里贴"示意代码"。
6. **每个阶段都要有量化验收**：录 rosbag，并给出可以复现的指标脚本。
